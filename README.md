# yangarch.net — 작업과 기록

정기석의 공개용 개인 홈페이지 첫 버전. 개인 서버의 [yangarch.net](https://yangarch.net/)에서 운영하는 정적 사이트다. Sites 스킬의 정적 제작·검수 방식을 사용하되, 사용자 지정 호스팅인 기존 nginx 서버를 사용한다.

## 첫 버전

- 메인 페이지: 소개, 대표 프로젝트 7개, 기록 방향, 연락 방법
- 각 프로젝트의 목적·발전 과정·공개 코드 링크를 담은 상세 페이지 7개
- 자전거·수영·만드는 일의 기록 목록과 전체 목록. 기록을 추가하면 작성일·본문·원문 링크를 담은 상세 페이지 생성
- 맥에서 실행하는 기록 편집기: 초안 저장·기존 글 수정·사진 배치·미리보기·선택한 글의 공개본 준비
- 준비된 공개본 목록 확인 후 SSH로 서버 반영. 배포 전용 수신기의 최초 설정 이후에는 편집기 버튼으로 진행
- 메인 목록과 상세 페이지에서 실제 서비스에 접속. poogiegram과 운동 리포트/fingu, cyber-topgoal 바로가기 제공
- 데스크톱/모바일 레이아웃, 키보드 접근, 프로젝트 분류
- 공개 연락 경로는 GitHub·LinkedIn. 전화번호·개인 이메일·내부 주소·개인 데이터는 포함하지 않음
- 기존 `/portfolio/giseok-chung-data-portfolio.pdf` 경로는 별도로 유지하며 새 배포물에 PDF를 복사하지 않음

실제 글과 사진은 로컬 초안에 보관하며, 공개 기록은 아직 빈 목록이다. 프로젝트 소개와 서비스 바로가기를 제공하며, 로그인은 각 서비스의 기존 인증을 사용한다.

## 파일 구조

- `content/public.json`: 공개용으로 따로 작성한 내용. career나 서버 자료를 자동으로 읽지 않는다.
- `content/records.json`: 공개하기로 선별한 글만 입력. 현재 `entries`는 빈 목록이다.
- `scripts/records.py`: 기록 분류·고유 주소·작성일·본문·원문 주소 검증.
- `editor/`, `scripts/editor.py`: 로컬 전용 글쓰기 화면과 저장 서버. 공개 사이트와 배포 패키지에 포함하지 않는다.
- `scripts/record_media.py`: 공개 사진 경로 및 JPEG 메타데이터 경계 검사.
- `scripts/record_import.py`: 디시·네이버 본문 추출과 외부 요청 허용 정책. 공개 배포물에는 포함하지 않는다.
- `scripts/publish.py`, `scripts/publication.py`: 선택한 공개본을 고정하고 정적 파일만 전송하는 로컬 배포와 전송 형식 검사.
- `scripts/publish_receiver.py`, `deploy/setup-publisher.sh`: 최초 설치하는 서버 전용 수신기와 제한된 권한 설정. 업로드된 코드를 실행하지 않는다.
- `assets/`: 직접 작성한 CSS·JS·SVG. 외부 폰트·CDN·분석 스크립트 없음.
- `scripts/build.py`: 명시된 파일과 문서만 `dist/`에 생성.
- `scripts/check.py`: 배포 파일 목록·해시·민감 패턴·HTML·링크·nginx 설정 일치 검사.
- `scripts/content_policy.py`: 로컬 공개 제외 문구를 검증하고 릴리스 검사에 전달. 제외 문구 자체는 Git에 넣지 않는다.
- `scripts/public_links.py`: 검토한 서비스 URL 7개만 정확히 허용. 임의 하위 도메인·포트·리디렉션 쿼리는 허용하지 않음
- `deploy/`: apex 전용 nginx 설정과 백업·되돌림을 포함한 설치 스크립트. 웹 루트 밖에 보관.
- `tests/nginx_integration.py`: 실제 nginx의 허용 경로·공격 경로·보안 헤더·요청 제한 검증.
- `artifacts/`: 비공개 검수 자료·배포 패키지. 웹에 제공하지 않는다.

Node 패키지 설치는 필요하지 않다. 공개 사이트의 빌드·미리보기는 Python 표준 라이브러리만 사용한다. 로컬 편집기는 사진 처리를 위해 프로젝트 전용 가상환경에 Pillow를 설치한다.

## Git으로 관리하는 범위

이 저장소는 소스·검증 코드·선별한 프로젝트 소개·개발 문서를 공개로 관리한다. 개인 글과 사진은 공개본 준비 여부에 관계없이 Git에서 제외하며 별도로 백업한다.

- 제외: `.local/`, `artifacts/`, `dist/`, `.impeccable/`, `.env`와 로컬 운영 문서.
- 제외: `content/records.json`, `content/record-media/`, `content/privacy.local.json`, 생성된 nginx 설정.
- 예제: `content/records.example.json`은 빈 기록, `content/privacy.example.json`은 가상의 제외 정책이다.
- 검사: `python3 scripts/repo_check.py`가 Git 인덱스의 파일과 내용을 검사한다. 강제로 추가한 제외 대상도 거부한다. 실제 개인정보를 모두 판별하는 도구는 아니므로 커밋할 변경도 직접 확인한다.

새로 복제한 환경에서는 먼저 아래를 실행한다. 기존 파일은 덮어쓰지 않는다.

```bash
python3 scripts/setup_local.py
```

개인별 공개 제외 문구는 `content/privacy.local.json`에서 관리한다. 기존 맥의 정책과 초안은 이 파일 및 `.local/editor/`의 별도 백업으로 복구한다. 자동 검사는 예제 데이터만 사용하고, 실제 원문을 가져오거나 서버에 배포하지 않는다. 기여 방법과 커밋 점검은 [CONTRIBUTING.md](CONTRIBUTING.md), 보안 경계는 [SECURITY.md](SECURITY.md)를 참고한다.

## 맥에서 글 쓰기

Finder에서 `start-editor.command`를 더블클릭하거나 이 폴더에서 `./start-editor.command`를 실행한다. 처음 한 번은 `.local/editor-venv`를 만들고 `requirements-editor.txt`의 사진 처리 패키지를 설치한다. 실행한 터미널을 열어 두고 `http://127.0.0.1:4180/`을 사용한다. 종료는 해당 터미널에서 Ctrl+C다.

1. **새 글:** 제목·분류·작성일을 입력한다. 다른 곳에서 옮긴 글은 원문 주소와 출처 이름도 입력한다.
2. **본문:** 텍스트를 붙여넣고 글·사진을 순서대로 추가한다. 각 항목의 위로·아래로·빼기로 배치를 조정한다. 사진은 JPG·PNG·WebP, 한 장에 20MB까지다. HEIC는 JPG로 변환한 뒤 선택한다.
3. **초안 저장:** 이 맥의 `.local/editor/posts/`에 저장한다. 원본 사진과 이전 저장본도 이곳에 보관한다. 저장만으로 공개용 JSON·dist·배포 패키지를 바꾸지 않는다.
4. **미리보기:** 초안을 저장하고, 실제 본문 레이아웃을 읽기 전용 창으로 보여준다.
5. **공개본 준비:** 미리보기에서 해당 글을 확인하고 ‘이 글의 공개본 준비’를 선택한다. 다른 글의 초안은 포함하지 않고, 이미 준비된 공개 글은 유지한다. 별도 임시 폴더에서 빌드·검사·패키징한 뒤 통과한 결과만 현재 공개 파일로 교체한다. 검사 실패 시 기존 공개본과 초안을 유지한다.
6. **서버에 반영:** 왼쪽의 ‘서버에 반영’에서 준비된 글 목록·작성일·사진 수를 확인한다. 연결 확인이 끝나면 ‘확인한 공개본 반영’을 누른다. 검사·전송·서버 검증 후 실제 기록 페이지 링크를 표시한다. 최초 서버 설정은 [배포 안내](docs/PUBLISHING.md)를 따른다.

### 다른 곳에 쓴 글 가져오기

왼쪽의 **URL에서 가져오기**를 누르고 디시 PC 게시글 주소나 네이버 블로그 글 주소, 기록 분류를 입력한다. 원문 주소를 이미 입력한 경우 그 아래의 **이 주소에서 새 초안 가져오기**도 사용할 수 있다. 제목·원문 작성일·본문·사진 순서와 출처를 새 초안에 저장한다. 현재 글의 저장하지 않은 변경 사항은 먼저 저장하며, 가져온 글로 덮어쓰지 않는다.

- 디시: 일반·마이너·미니 갤러리의 PC 글 주소. 네이버: 일반 글 주소·모바일 공유 주소·PostView 주소를 지원한다. 본문 추출은 현재 SmartEditor ONE 형식을 기준으로 한다.
- 원문의 문구를 요약하거나 교정하지 않는다. 본문 HTML은 실행하지 않고 텍스트·줄바꿈·사진만 읽는다. 글꼴·색상은 홈페이지 스타일을 따른다. 댓글·광고·프로필 이미지는 제외한다.
- 디시의 지연 로딩 사진, 네이버의 흐림 썸네일과 실제 표시용 사진 주소를 구분한다. 사진은 글에서 제공하는 표시용 파일을 내려받아 보관하며, 공개용 사본은 기존 메타데이터 제거 과정을 거친다.
- 같은 원문을 다시 가져오면 먼저 가져온 초안을 연다. 그동안 수정한 내용은 유지한다. 검색·페이지 번호 같은 URL 매개변수는 중복 판단에서 제외한다.
- 사진 한 장이라도 가져오지 못하면 새 초안을 만들지 않고 오류를 알린다. 기존 초안과 공개본은 유지한다. 동영상·표·움직이는 이미지 등 현재 보존할 수 없는 내용도 누락시키지 않고 오류로 알린다. 사진은 최대 100장, 한 장 20MB, 전체 전송량 100MB로 제한한다.
- 가져오기는 로그인 없이 열리는 글만 지원한다. 가져온 뒤에도 공개본 준비와 서버 배포는 별도 동작이다.

**공개본 준비는 서버 배포가 아니다.** 준비된 파일은 4173 미리보기에 반영되며, 실제 yangarch.net에는 ‘서버에 반영’을 별도로 실행해야 한다. 이미 준비한 글을 다시 수정해 저장해도 이전 공개본은 다음 ‘공개본 준비’ 전까지 유지된다.

편집기는 `127.0.0.1`에만 바인딩한다. Host·Origin·세션 쿠키·CSRF 토큰을 확인하고 CORS를 허용하지 않는다. 포트를 인터넷에 열거나 nginx에서 프록시하지 않는다. 편집기 세션은 실행할 때마다 바뀐다. 외부 요청은 사용자가 ‘가져오기’를 선택한 디시·네이버 글과 해당 플랫폼의 허용된 사진 호스트로 제한한다. 리디렉션마다 주소를 검사하고 내부 IP를 차단하며, 검증한 공개 IP에 연결한 뒤 원래 호스트 이름으로 TLS 인증서를 검증한다. 로컬 쿠키·인증 정보는 외부에 보내지 않는다.

사진 원본은 맥의 로컬 비공개 폴더에 남기며 편집기가 읽어서 새 JPEG 사본을 만든다. 방향을 바로잡고 최대 2048px로 줄인 뒤 EXIF·GPS·XMP 등 메타데이터를 제거한다. 본문에 넣은 사본만 `content/record-media/`와 공개물에 포함한다. 글·사진을 본문에서 빼도 로컬 원본은 지우지 않는다.

초안 보관에는 `.local/editor/`를 따로 백업해야 한다. Git이나 공개 사이트 패키지에는 포함되지 않는다. 현재 편집기에는 글 삭제·공개 철회 기능을 넣지 않았다. 서버 반영은 사용자가 준비된 목록을 확인하고 실행할 때만 진행하며, 저장·가져오기·공개본 준비만으로 시작하지 않는다.

편집기 검증까지 실행하려면 `.local/editor-venv/bin/python -m unittest discover -s tests -p 'test_*.py'`를 사용한다. 사진 처리 패키지가 없는 기본 Python에서는 사진 처리가 필요한 편집기 검증을 건너뛴다.

## 로컬 제작

```bash
python3 scripts/setup_local.py
python3 scripts/build.py
python3 scripts/nginx_config.py
python3 scripts/check.py
node --check assets/site.js
python3 scripts/preview.py
```

미리보기: `http://127.0.0.1:4173`.

내용 변경 후에는 build → nginx_config → check 순서로 실행한다. 공개 URL 목록도 빌드 결과와 함께 갱신되며 불일치 시 패키징이 중단된다.

서비스 링크·기록 검증: `python3 -m unittest discover -s tests -p 'test_*.py'`. 설치 시와 같은 격리 모드 검사: `python3 -I scripts/check.py`.

서비스 링크의 현재 연결 대상은 `content/public.json`의 `services`에 명시한다. 구직 에이전트에는 웹 주소를 만들지 않는다. 투자 대시보드 `njc.yangarch.net`은 HTTPS 인증서의 호스트 불일치가 확인되어 현재 동작하는 HTTP 링크로 표시했다. 인증서 검증을 끄거나 경고 화면을 우회하지 않았다. 다른 서비스 6개는 HTTPS 첫 화면 또는 인증 응답을 확인했다.

## 개발 기록과 배포 상태

현재 구현과 선택한 구조, 다음 작업은 [개발 기록](docs/DEVELOPMENT.md)에 정리한다. 커밋은 현재 구현을 기준으로 시작하며, 이전 작업을 과거 커밋으로 재구성하지 않는다.

2026-11-03 운영 서버에 첫 버전을 반영했고, 2026-11-04 외부 HTTPS 검증을 완료했다. 공개 URL 16개의 응답이 검사된 파일 해시와 일치하며, 비공개 경로 9개의 404 응답과 보안 헤더를 확인했다. 기존 PDF는 원본 해시를 유지한다. 실제 글·사진과 로컬 편집기는 배포하지 않았다. 서버 계정·임시 배포 경로·검토용 로그는 로컬에 보관한다.

배포 패키지는 `python3 scripts/package.py`로 만든다. 검사된 정적 파일과 설치·검사에 필요한 파일만 포함한다. 패키지의 콘텐츠 제외 정책도 웹 루트 밖에 보관하며, 전체 프로젝트를 업로드하지 않는다. 다른 서비스·DNS·인증서는 이 저장소의 자동화에서 변경하지 않는다.

## 기록 추가

메인 분류 → 분류별 목록 → 본문으로 이동한다. `/records/`는 전체 목록이며 분류 경로는 `/records/cycling/`, `/records/swimming/`, `/records/making/`다. 각 목록에서 다른 분류와 전체 목록으로 이동할 수 있다. 글이 없으면 빈 목록 안내를 표시한다.

공개할 글을 선별해 `content/records.json`의 `entries`에 추가한다. 필드는 `id`(고유한 영문 소문자·숫자·하이픈), `category`(`cycling`·`swimming`·`making`), `title`, `date`(원문 작성일, `YYYY-MM-DD`), `body`(문단별 텍스트 배열)다. 외부에 먼저 쓴 글은 `source`에 `label`과 `url`을 추가한다. 직접 쓴 글은 `source`를 생략한다.

본문 주소는 `/records/entry/<id>/`이며 날짜순으로 목록을 생성한다. 원문 주소는 네이버 블로그·티스토리·디시인사이드의 HTTPS URL만 허용하고, 각 글에서 지정한 정확한 URL을 manifest에 기록해 링크 검사와 배포 패키지에도 반영한다. 다른 출처가 필요하면 허용 정책을 먼저 검토한다.

원문 HTML은 삽입하지 않는다. 제목·문단·출처 이름을 이스케이프하며 본문은 텍스트 문단·줄바꿈·로컬 사진을 지원한다. 사진 항목은 `type: image`, `src`, `alt`, `caption`이며 편집기가 만든 `/media/records/<id>/<사진ID>.jpg` 주소만 허용한다. 비공개 보관 자료와 커뮤니티 글을 자동으로 게시하지 않는다.

추가 후 build → nginx_config → check → package를 실행한다. 단위 검증용 기록은 임시 디렉터리에서만 빌드하며 실제 공개물에 샘플 글을 넣지 않는다.
