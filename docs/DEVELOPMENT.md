# 개발 기록

## 현재 상태

개인 서비스를 찾아 들어가는 홈페이지와 기록 열람 화면, 맥에서 글을 작성하는 편집기가 구현되어 있다. 첫 구현은 GitHub 비공개 저장소에서 시작했고, 공개 범위를 검토한 뒤 소스와 개발 이력을 공개로 관리한다.

2026-11-03 [yangarch.net](https://yangarch.net/)에 첫 버전을 배포했다. 2026-11-04 외부 HTTPS와 브라우저 확인을 마쳤다. 실제 글은 로컬 초안이며 Git과 공개 기록에서 제외한다.

## 첫 운영 배포

첫 설치에서는 nginx 재적용 직후의 검사가 이전 응답을 받아 실패했고, 설치 스크립트가 이전 설정으로 복구했다. 새 홈페이지의 HTTP 200 응답과 본문 일치를 제한 시간 안에 확인한 뒤 나머지 검사를 시작하도록 수정했다. 잘못된 200 응답은 준비 완료로 취급하지 않으며 TLS 검증도 유지한다. 이 동작을 검증하는 테스트 4개를 추가했고 전체 34개 테스트와 CI가 통과했다.

수정한 패키지는 별도 nginx 환경에서 허용 경로·차단 경로·보안 헤더·메서드 제한·요청 제한을 검사한 뒤 반영했다. 운영 서버의 새 홈페이지와 공개 페이지 응답을 확인했고, 외부 HTTPS에서는 공개 URL 16개의 파일 해시 일치, 비공개 경로 9개의 404 응답, 보안 헤더를 확인했다. 기존 PDF는 원본 해시와 일치한다. 브라우저에서 홈·프로젝트 상세·기록 목록 이동도 확인했다.

서버에는 정적 공개 파일만 두며, 로컬 편집기·초안·원본 사진은 포함하지 않는다. 기록 목록은 아직 비어 있다. 글을 공개하려면 선택한 글의 공개본 준비와 별도 배포가 필요하다.

## 2026-11-04: cyber-topgoal 추가

개인 음악 플레이어 cyber-topgoal을 메인 목록과 별도 소개 페이지에 추가했다. 서비스 접속 주소와 공개 GitHub 저장소를 연결하고 로그인 후 사용하는 서비스임을 표시한다. 공개 항목은 총 7개이며, 처음 표시하는 프로젝트 수도 콘텐츠 개수에서 계산한다.

서버 소스와 HTTPS 로그인 화면을 확인했으며 음악 목록·방명록 API는 비인증 요청에 401을 반환한다. 음악 파일·방명록 데이터는 홈페이지에 복사하지 않는다. 기존 34개 테스트와 공개 파일 검사를 통과했고 브라우저에서 목록·분류 필터·상세 페이지를 확인했다. 같은 날 별도 설치 패키지로 운영 반영을 완료했다. 외부 HTTPS 공개 URL 17개의 해시 일치, 비공개 경로 9개의 404 응답과 보안 헤더, 기존 PDF의 원본 해시 보존을 확인했다. 실제 도메인의 메인 목록과 상세 페이지도 브라우저에서 확인했다.

## 2026-11-04: 저장소 공개

사용자가 소스 공개를 결정했다. 전환 전 전체 5개 커밋, Issue·댓글, Actions 로그 5건과 첨부물 유무를 확인했다. 비밀값·로컬 공개 제외 문구 검사에서 문제는 발견되지 않았으며, 개인 글·사진·초안·실제 제외 정책은 Git에 포함하지 않는다. 커밋 작성자 이메일은 GitHub의 비공개 이메일 주소를 사용한다.

로컬 편집기는 loopback에서만 실행하며 세션·Origin·CSRF 토큰을 검증한다. 운영 서버에는 편집기와 업로드 API를 제공하지 않는다. 배포 경로와 보안 설정의 공개 여부도 검토했으며, 인증 정보와 실제 운영 자료는 계속 별도로 보관한다. 라이선스는 이번 공개 전환에서 추가하지 않는다.

## 2026-11-05: 편집기에서 서버 반영

공개본 목록·사진 수를 확인하고 SSH로 반영하는 버튼을 추가했다. 배포할 정적 파일을 고정한 뒤 전송하며, 초안이나 로컬 제외 정책을 전송하지 않는다. 서버에는 root 소유의 무인자 수신기만 최초 설치한다. 업로드된 코드를 실행하지 않고 파일 경로·크기·해시를 검사해 홈페이지 경로만 갱신한다. 실제 nginx 반영·reload·검증 실패 시 복구를 별도 환경에서 확인했다. 최초 관리자 설정과 실제 운영 연결 검증은 별도로 진행한다. 절차와 권한 범위는 [배포 안내](PUBLISHING.md)에 정리한다.

## 선택한 구조와 이유

### 정적 공개 사이트와 로컬 편집기

주로 맥에서 글을 정리한다는 사용 방식에 맞췄다. 편집기와 원본은 맥에 두고, 공개할 파일만 개인 서버의 기존 nginx에서 제공한다. 공개 서비스에 들어가는 실행 코드와 데이터를 줄이고, 초안을 저장하는 행동과 외부 공개를 분리한다.

### 원문과 사진의 로컬 보관

커뮤니티·블로그의 기록을 다시 읽기 위해 본문과 사진을 내려받는다. 원문의 문구를 요약하거나 교정하지 않는다. 사진 파일을 따로 보관하고, 공개할 때는 메타데이터를 제거한 사본을 사용한다. 가져오기에 실패한 항목을 조용히 누락시키지 않는다.

### 선택한 공개본의 스냅샷

초안을 수정하는 동안 이전 공개본을 유지한다. 공개본 준비는 임시 공간에서 검사를 끝낸 뒤 반영하고, 교체 중 오류가 발생하면 이전 상태로 되돌린다. 실제 서버 반영은 별도 절차다.

### 코드 이력과 개인 자료의 분리

GitHub에는 소스·예제 데이터·검증 코드·개발 문서를 남긴다. 글·사진·로컬 제외 정책은 별도 백업 대상이다. 새 복제본은 빈 기록으로 실행하며, 개인 자료 복구는 저장소 복제와 별도로 진행한다.

## 검증 방법

- Python 단위 검증: 기록·편집기·가져오기·네트워크 경계·저장소 경계.
- 공개 파일 검사: manifest·해시·내부 링크·CSP 호환 소스·제외 문구.
- 배포 패키지: 임시 폴더에 풀어 격리 모드로 다시 검사.
- Git 인덱스: 제외 대상 강제 추가·바이너리·민감 패턴 검사.
- 새 복제본: 로컬 초안 없이 예제 설정으로 빌드·검증.

브라우저 검토 이미지와 실제 운영 환경의 검증 기록은 로컬 개발 자료로 보관한다. 예전 운영 검증 결과를 현재 버전의 배포 완료로 취급하지 않는다.
