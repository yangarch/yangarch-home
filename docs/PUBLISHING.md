# 편집기에서 서버에 반영하기

초안을 저장하고 공개본을 준비한 다음, 편집기 왼쪽의 **서버에 반영**을 사용한다. 준비된 모든 글과 사진을 함께 반영한다. 초안만 저장한 글과 공개본 준비 이후에 수정한 내용은 포함하지 않는다.

1. 공개할 글을 미리보기로 읽고 **공개본 준비**를 실행한다.
2. **서버에 반영**에서 글 목록·작성일·사진 수를 확인한다.
3. 서버 연결 확인이 완료되면 **확인한 공개본 반영**을 누른다.
4. 검사·전송·반영·응답 검증이 끝나면 **실제 기록 페이지 열기**로 확인한다.

준비된 글이 없으면 기록이 없는 사이트로 갱신한다는 안내를 표시한다. 확인 창을 연 뒤 공개본이 바뀌면 목록을 다시 확인해야 한다. 같은 편집기와 서버에서 중복 배포를 허용하지 않는다.

## 최초 한 번의 서버 설정

설정 파일과 수신기 코드를 검토하고, 서버의 비공개 준비 폴더에서 `sudo bash deploy/setup-publisher.sh`를 실행한다. 최초 설정에만 터미널에서 sudo 비밀번호를 입력한다. 설치는 현재 홈페이지를 게시하거나 바꾸지 않으며, 실패 시 이전 수신기·sudo 규칙·기준 설정을 복원한다.

설치되는 항목은 다음과 같다.

- root 소유 버전별 수신기와 검증 모듈: `/usr/local/lib/yangarch-home/versions/`.
- 인자를 받지 않는 실행 파일: `/usr/local/sbin/yangarch-home-publish`.
- 이 실행 파일 하나만 허용하는 `/etc/sudoers.d/yangarch-home-publish` 규칙.
- root 전용 상태·복구 자료: `/var/lib/yangarch-home/`.

설정 도중 sudo 규칙 문법과 실제 배포 사용자의 비대화형 상태 조회를 검사한다. 인증 정보를 소스·서버 패키지·웹 루트에 넣지 않는다.

맥의 `.local/editor/publish.json`에는 기존 SSH 설정의 별칭만 입력한다. 아래는 예제이며 이 파일은 Git에서 제외한다.

```json
{"ssh_host":"personal-server"}
```

맥에서 해당 별칭으로 SSH 키 로그인이 가능하고 호스트 키가 등록되어 있어야 한다. 키 인증을 사용할 수 없으면 편집기에서 오류를 표시하며 비밀번호를 묻거나 저장하지 않는다.

## 전송과 권한 범위

기존 수동 관리용 tar 패키지를 root로 실행하는 방식과 분리했다. 버튼 배포는 공개 manifest에 있는 정적 파일만 고정한 뒤 표준 입력으로 전송한다. root 소유 수신기는 업로드된 스크립트·경로 설정을 실행하거나 설치하지 않는다. 파일 경로 허용 목록·크기·개수·해시 검사를 통과한 데이터만 새 홈페이지 릴리스에 기록한다.

새 경로 스니펫과 현재 릴리스 링크를 반영하고 nginx 설정 검사·reload·실제 TLS 응답·공개 파일 해시·비공개 경로 차단·기존 PDF 보존을 확인한다. 실패하면 이전 링크와 스니펫을 복원한다. 다른 서비스·DNS·TLS 인증서에는 쓰지 않는다.

서버 반영이 완료된 뒤 맥에서도 기록 목록과 글의 외부 HTTPS 응답을 확인한다. 통신이 끊기면 단순 실패와 반영 완료를 구분할 수 없을 수 있다. 이 경우 연결 확인과 실제 사이트 확인을 안내하며, 이전 버전이 유지됐다고 단정하지 않는다.

## 검증

- `python -m unittest discover -s tests -p 'test_*.py'`: 경로 조작·변조·전송 한도·중복 작업·공개본 변경·SSH 인자·복구 및 기존 편집기 접근 검사.
- Linux의 별도 nginx 환경에서 `python3 tests/publisher_nginx_integration.py`: 실제 수신기 반영·새 글 경로·reload·실패 후 복구. 운영 설정을 변경하지 않는다.

서버 관리용 설정이 바뀌면 수신기는 기존 기준과 달라진 것을 감지해 배포를 거부한다. 변경 내용을 검토한 뒤 최초 설정을 다시 실행한다. 과거 릴리스와 복구 자료의 삭제·정리 기능은 포함하지 않는다.
